# Changelog

All notable changes to the server workspace are recorded here.
## Unreleased

### <u>build-release</u>

#### Added

- `release.mjs` gained a `--package <name>` option to select which packages a run produces: repeatable and/or comma-separated (`--package deb --package portable`, `--package "deb,portable"`), known names coming from the configuration (`dmg`, `nsis`, `msi`, `deb`, `rpm`, `appimage`) plus `portable` (portable archive) and `app` (macOS `.app` archive), and `all`/`*` keeping the default of every declared package. Unknown names abort with the list of known names; packages no selected target can produce are reported as a warning; platforms left with nothing to produce are skipped without compiling; `--list` (`produces:`) and `--dry-run` (`packages=[...]`) reflect the selection; the production method stays based on the declared bundles (selecting `portable` alone never switches a platform to Docker or unbuildable); and cleanup only removes the selected packages, so artifacts left out of the selection stay in place from previous runs.
- `release.mjs` and `install-tools.mjs` now install the Rust toolchain when `cargo` is missing on a Linux/macOS host instead of failing: `ensureRustToolchain()` in `lib.mjs` offers the official rustup installer (`curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh -s -- -y`, with a `wget` fallback) through the standard `[y/N]` confirmation, then prepends `~/.cargo/bin` to the process PATH so the run continues without restarting the shell. Refusing the prompt, a non-interactive terminal, or a Windows host keep the previous `` `cargo` is not installed `` error (Rust on Windows stays installed through `winget` as documented in `server/README.md`).
- `install-tools.mjs` (and `release.mjs --no-install`) now ensure the host Tauri CLI (`cargo tauri`) whenever a selected platform builds natively: `ensureTauriCli()` in `lib.mjs` probes `cargo tauri --version` and, when the `cargo-tauri` binary is missing or older than the `tauriCliVersion` from `build-config.json`, offers `cargo install --locked --version <version> tauri-cli` through the standard `[y/N]` confirmation (same version as the cross image). Previously the CLI version was only forwarded to the Docker image, so a native Linux run without `cargo-tauri` failed late with `error: no such command: 'tauri'`; a refusal or non-interactive terminal keeps a contextualized error with the install command.
- `release.mjs` and `install-tools.mjs` now redirect cargo's target directory to a local filesystem when the workspace `target/` sits on an unreliable mount (VirtualBox shared folder `vboxsf`, VMware `vmhgfs`, NFS/CIFS/SSHFS, exFAT/vFAT/NTFS): `ensureLocalTargetDir()` in `lib.mjs` detects the mount with `stat -f -c %T` and, after the standard `[y/N]` confirmation, sets `CARGO_TARGET_DIR` to `~/.cache/arachnea-target` (inherited by every spawned `cargo`). Without this, build-script outputs written into the shared mount silently vanish — `serde_core`'s `OUT_DIR/private.rs` stays missing so the build fails with `couldn't find file .../out/private.rs` even after `cargo clean`, since each rebuild recreates the same empty `out/` directory. An explicit user-provided `CARGO_TARGET_DIR`, a refusal, or a non-interactive terminal keep a contextualized error with the `export` command instead of building into the broken mount.
- When a Docker cross build is actually required (a selected platform resolves to `method: docker`) but the `docker` CLI is missing on a Linux host, the tooling now installs Docker Engine itself after the standard `[y/N]` confirmation: it runs the official `get.docker.com` script through `sudo`, ensures the `docker` group exists and the current user belongs to it (`groupadd -f` + `usermod -aG`), starts the daemon when needed, and — because a new group membership only applies to a fresh login session — re-launches the run once through `sg docker -c ...` so no logout is required (`ARACHNEA_DOCKER_GROUP_REEXEC` keeps it one-shot). Windows/macOS keep the explicit "install Docker" error (Docker Desktop).


#### Changed

- Release tooling versions are now centralized in `build-release/build-config.json` (minimum rustc, cross image tag, in-image Tauri CLI) instead of constants scattered across `lib.mjs`/`docker.mjs`/`Dockerfile`; the Docker image build forwards the Tauri CLI version as a build arg.
- Platform selection is now host-aware and positional: `-p`/`--platform` were removed, and both `release.mjs` and `install-tools.mjs` take plain target arguments (exact ids, family names/`osx`, `*` for every configured platform, trailing-`*` patterns, several targets space- or comma-separated). With no target, `release.mjs` builds only the platform matching the host OS and CPU (`windows-x86_64` on a 64-bit Windows host, `darwin-arm64` on Apple Silicon, `darwin-x86_64` on Intel Macs, `linux-arm64`/`linux-x86_64` on Linux) instead of every configured platform, so building everything now requires `release.mjs "*"`. The host mapping lives in `capabilities.mjs` (`hostPlatformSelector`) and is applied through `lib.mjs`'s `defaultSelectors`; an unknown host CPU falls back to the host family and an unsupported host OS keeps the previous "all platforms" behavior with a warning. `--list` keeps listing every configured platform (filtered when targets are given), `install-tools.mjs` keeps provisioning every platform the host can build when called without target, and the `package.json` scripts pass their id positionally. Using a removed flag fails with an explicit message pointing at the new syntax.
- The final build summary now appends, on every successful target, the packages that target produced (`packages=[...]`, same names as in `--dry-run`, e.g. `success packages=[nsis, msi, portable]`); failed targets keep showing only their error.
- `install-tools.mjs` (and therefore `release.mjs`) now provisions the frontend workspace dependencies before the shared frontend build: `ensureFrontendDeps()` runs `npm install` in `front/`, `front/public-app` and `front/admin-app` after a single `[y/N]` confirmation, because the app build scripts spawn their local `run-p` binary (from the `npm-run-all2` devDependency) and a checkout without `node_modules` stopped the whole release with `'run-p' is not recognized as an internal or external command`. Workspaces whose `node_modules` is already up to date (`node_modules/.package-lock.json` newer than `package.json`) are skipped, `front/` has no npm workspaces field so each directory installs its own dependencies, and the step is skipped entirely with `--skip-build` / `--no-frontend-build` (or `--no-install`).

#### Fixed

- Windows PowerShell ZIP fallback now passes source and destination paths through dedicated child-process environment variables instead of interpolating them into PowerShell code. Apostrophes and shell metacharacters remain path data, source directory wildcard characters are escaped, and archive errors fail the release command.

- The shared release command runner now explicitly disables implicit shells after applying caller options. Windows npm installation and build steps invoke `cmd.exe` with fixed commands and pass project paths separately as working directories.

- The repository-root macOS/Linux `build.sh` wrapper now accepts both quoted
  and unquoted all-platform selectors (`./build.sh '*'` and `./build.sh *`). It
  preserves arguments through `"$@"` and recognizes the complete filename list
  produced when the invoking shell expands an unquoted `*`, replacing it with
  the release builder's literal wildcard instead of reporting every repository
  entry as an unknown platform.
- macOS `.app.tar.gz` archives with the accented `Arachnéa.app` bundle name no
  longer fail during POSIX mode normalization: TAR path fields are decoded as
  UTF-8 and compared in NFC form, instead of decoding the UTF-8 name as Latin-1
  and incorrectly reporting the inner executable as absent.
- Release tooling now checks the active rustc version before building: when it is older than the `minRustcVersion` floor in `build-config.json` (1.91.0, required by the locked `foyer@0.22.4+` dependency), it offers to run `rustup update` with confirmation instead of failing late inside `cargo tauri build`.
- The Linux system dependency install no longer requests the legacy `libappindicator3-dev`: on Linux Mint/Ubuntu (noble) apt aborted with `libayatana-appindicator3-1 : Est en conflit avec: libappindicator3-1`, breaking the whole `apt-get install`. It now installs `libayatana-appindicator3-dev` (Tauri's documented prerequisite, same package as the cross image and `docs/BUILDING.md`).
- The Linux system dependency install now includes `libssl-dev` and `pkg-config`: native builds failed in `openssl-sys v0.9.117` with `Package openssl was not found in the pkg-config search path` — the crate locates OpenSSL through `openssl.pc`, so the runtime-only `libssl3` is not enough (same pair as `docs/BUILDING.md` / `server/README.md`).
- The Linux system dependency install now includes `git`, `clang` and `libclang-dev`: `boring-sys2 v5.0.0-alpha.10`'s build script panicked with `Os { code: 2, kind: NotFound }` at `build/main.rs:662` (`ensure_patches_applied(&config).unwrap()` — the very first step of `main()`, which applies BoringSSL patches through `git`), and later needs `libclang` for `bindgen`; the Mint host had neither `git`/`clang` (`which` empty) nor any `libclang*` on disk.
- Native build tools now also cover the BoringSSL prerequisites (`go`, `perl`, C++ compiler): BoringSSL's CMake runs `find_package(Perl REQUIRED)` and generates `err_data.c` through `go run err_data_generate.go`, so both commands must be on PATH for `boring-sys2 v5.0.0-alpha.10` to configure (the build then panicked with `Os { code: 2, kind: NotFound }` at `build/main.rs:662`), while `install-tools` only checked `cmake`/`ninja`/`nasm` and reported them as found. `NATIVE_BUILD_TOOLS` probes `cmake`, `ninja`, `nasm`, `go`, `perl`, `c++` (installed as `ninja-build`, `golang-go`, `g++` on apt; same names through Homebrew) and on Windows they are installed through winget (`Kitware.CMake`, `Ninja-build.Ninja`, `NASM.NASM`, `GoLang.Go`, `StrawberryPerl.StrawberryPerl`) after the standard `[y/N]` confirmation — elevated through a UAC prompt when the shell is not administrator, since the Go/Perl MSIs install machine-wide, and with the resulting directories (Strawberry Perl's `c\bin`, a GCC toolchain, excluded on purpose) prepended to the run's PATH because winget only refreshes the machine PATH for new shells. On Windows the VS-provided `ninja` and the MSVC `cl.exe` of the detected Visual Studio toolset count as present for `ninja`/`c++` (there is no `c++` command there, and CMake/rustc locate `cl.exe` through the VS installation rather than PATH); a tool still missing afterwards is reported with its winget id.
- `install-tools.mjs` no longer demands Docker when every selected platform resolves to the native method: `ensureDockerCrossBuild` filtered on the static `needsDockerBuild` eligibility (`"build": "docker"` in `release-config.json`), so the default `linux-x86_64` run on a Linux host — fully native, Docker never invoked — aborted with "Docker is required to produce the portable Linux/macOS binaries". It now filters on the resolved `method: docker`, and Docker is only provisioned for platforms actually built in the cross image.
- `install-tools.mjs` skips the Linux system package install when `dpkg-query` reports every package as already installed: previously each run prompted for confirmation then ran `sudo apt-get update` + `apt-get install -y` (with password prompt) only for apt to answer `0 mis à jour, 0 nouvellement installés`. Only actually missing packages are now offered/installed.
- Linux installer bundles (`.deb`/`.rpm`) now override `productName` with the ASCII `arachnea` from `release-config.json` through the Tauri `--config` merge: the Tauri Debian bundler copied the accented `Arachnéa` from `tauri.conf.json` verbatim into the control `Package:` field, which `dpkg` rejects (only `[a-z0-9+.-]` allowed), and staged resources under `/usr/lib/Arachnéa/`. Applies to native Linux builds and Docker cross-bundle passes (`crossBundleArgs`/`describeCrossBundling`); macOS/Windows builds keep the `Arachnéa` display name.
- Cross image rebased from `joseluisq/rust-linux-darwin-builder:2.0.0-beta.1` (Debian 13 Trixie) to `1.89.0` (Debian 12 Bookworm): linuxdeploy bundled the newer `libgcrypt.so.20` without the matching `libgpg-error >= 1.49`, so the AppImage aborted at launch on older distros such as Linux Mint with `symbol lookup error: undefined symbol: gpgrt_add_post_log_func, version GPG_ERROR_1.0`. The Bookworm base aligns the bundled crypto stack with the oldest supported distro. Rebuild the image (`arachnea-cross-builder:1.0.1`); discard the stale `1.0.0` tag since the 2.x-based layers are incompatible.
- Cross image Bookworm base now installs `libayatana-appindicator3-dev` (Tauri tray support) and `libsystemd-dev`: the Trixie base carried them transitively, while the Bookworm link failed with `rust-lld: error: unable to find library -lsystemd` (via `libdbus-1`). Image tag bumped to `arachnea-cross-builder:1.0.2`.
- Portable `.tar.gz` archives built on Windows are now usable: `createArchive` / `createTarGz` normalize the POSIX modes recorded in the archive (`normalizeTarGzModes`), because Windows has no permission bits and its `bsdtar` stores every entry as `0666`/`0777` — the amd64 archive produced on a Windows host therefore held a **non-executable** `arachnea`. That broke `arachnea-docker`'s image build (`test -x /tmp/app/arachnea` aborted the `fetcher` stage with `exit code: 1` and no diagnostic, since the check only runs under `set -e`) and would also have handed Linux users an archive that does not run after extraction. Windows' `bsdtar` (3.8.8) rejects `--mode`, so the modes are rewritten in the archive itself — a pure-Node helper reading the gzipped tar with `node:zlib`, setting files to `0644`, directories to `0755` and the entries listed by the caller to `0755` (macOS and GNU tar values), which makes the archive independent of the build host, and recomputing each header checksum. `release.mjs` passes the release executable for the portable archive and `Arachnéa.app/Contents/MacOS/arachnea` for the macOS `.app` archive; a missing expected entry fails the build instead of shipping a silently broken archive.
- `install-tools.mjs` no longer offers to reinstall native build tools that are already installed on Windows: `ensureNativeBuildTools()` probed `go`/`perl` with `where` before anything else, so a shell started *before* the install (VS Code's integrated terminal, typically) kept its stale `PATH` and reported them missing on every run — the `Install winget packages: GoLang.Go, StrawberryPerl.StrawberryPerl? [y/N]` prompt came back each time even though `C:\Program Files\Go\bin\go.exe` and `C:\Strawberry\perl\bin\perl.exe` were on disk (the installers had updated the *machine* PATH, which only reaches newly started shells). The known install directories (`windowsNativeToolDirs()`: Go, Strawberry `perl\bin`, NASM, CMake, `ninja-build`, and winget's `Links` shim directory) are now prepended to the run's `PATH` **before** that check (`prependWindowsNativeToolDirs()`), which also lets the build itself find the tools without restarting the shell, since BoringSSL's CMake runs `find_package(Perl REQUIRED)` and spawns `go run`.

### <u>arachnea-docker</u>

#### Added

- Multi-arch (`linux/amd64` + `linux/arm64`) runtime image for the prebuilt portable Linux `arachnea` server: one Dockerfile where `TARGETARCH` selects the baked-in archive. The runtime stays minimal (Debian `trixie-slim` base, one `apt` layer, no build toolchain), ships Debian's `chromium` for the `chaser-cf` Cloudflare solver with one entrypoint-owned `Xvfb` on `:99` for its headed virtual display, runs as the non-root `arachnea` user (Chromium's user-namespace sandbox still needs the container's seccomp profile unconfined — see the `Fixed` entry), persists state in `/app/data`, and uses `tini` as PID 1.
- Build configuration as Compose variables: `ARACHNEA_VERSION` and `ARACHNEA_RELEASES_DIR` live in the committed `arachnea-docker/.env` (template `.env.example`) or the environment, with no default and a fail-fast error when missing. The version expands into the two `ARACHNEA_AMD64_ARCHIVE` / `ARACHNEA_ARM64_ARCHIVE` paths (declared in `docker-compose.yml`, relative to the `releases` named build context), is stamped as `ENV ARACHNEA_VERSION`, and becomes the image tag: `image: arachnea-stream:${ARACHNEA_VERSION}` plus a `latest` alias via `build.tags`, so `docker compose up` runs the release just built. The archives are read straight from the release tree instead of a `bin/` staging folder; Buildx fails the build on a wrong path (`failed to compute cache key`), and the extracted binary's ELF `e_machine` is checked against the target port (`3e00` amd64 / `b700` arm64) so a swapped archive aborts the build instead of failing later with `exec format error`.
- `arachnea-docker/docker-entrypoint.sh`: wires `CHROME_BIN`, `CHASER_VIRTUAL_DISPLAY=0` and `CHASER_EXTRA_ARGS` (always ensuring `--disable-dev-shm-usage`), starts/reuses the one Xvfb display, and pins `ARACHNEA_PORT`/`ARACHNEA_NETWORK`/`ARACHNEA_ROOT` (all from the committed `.env`, empty root drops the key) into `/app/data/config.json` (the only reliable channel for those settings: `arachnea` rejects `--server-port 8080` with `unknown argument: 8080`). The published `ports:` mapping follows `ARACHNEA_PORT` on both sides.
- Stamped `HEALTHCHECK` (HTTP probe on `127.0.0.1:$ARACHNEA_PORT` via `/bin/bash`, valid in every `ARACHNEA_NETWORK` mode), Compose service (`ports`, `shm_size`), `.dockerignore`, `.gitignore`, and `README.md` (release-tree layout, named context, versioned tags, run notes).
- `arachnea-docker/build-image.sh` and `arachnea-docker/build-image.cmd`: build wrappers around `docker compose build` that resolve the release version to package. `--version=<version>` (or `--version <version>`) wins; otherwise the highest `release-*` folder of the release tree is picked (`../releases`, or `ARACHNEA_RELEASES_DIR` from the environment or `.env`, same precedence as Compose), and the script stops with an explicit error when neither is available. The resolved version is exported as `ARACHNEA_VERSION` (the environment wins over `.env`, so the image tag, the two archive paths and the stamped `ENV ARACHNEA_VERSION` all follow it), the two Linux portable archives are checked before the Docker build starts (clear message instead of a Buildx `failed to compute cache key`), any other argument is forwarded to `docker compose build` (e.g. `--no-cache` to rebuild every layer instead of reusing the cache of a previous release, `--progress=plain` or `--push` for the output), and the script ends by printing the version-pinned `docker compose up -d` line that starts the image just built.

#### Changed

#### Fixed

- `arachnea-docker` now keeps version resolution exclusively in `build-image.sh` / `build-image.cmd`: each wrapper selects the highest `release-*` directory when no version is passed, builds the versioned tag and its `latest` alias, while a bare `docker compose up -d` always starts the local `arachnea-stream:latest` image. The wrappers explicitly use the Buildx builder associated with the active Docker context and verify both tags in the local image store, preventing a globally selected `docker-container` builder from reporting success while retaining the image only in its private BuildKit cache. `pull_policy: never` prevents Compose from pulling or rebuilding a nonexistent `release-latest` archive pair.
- `docker-compose.yml` now sets `security_opt: [seccomp=unconfined]`. The image starts Chromium and Docker's *default* seccomp profile blocks the `clone`/`unshare` syscalls it needs to create its user-namespace sandbox, so the browser aborted with `No usable sandbox! ... you can try using --no-sandbox` and every Cloudflare fetch failed with `Failed to initialize browser: Browser process exited with status ExitStatus(unix_wait_status(256))` — reproduced on a Windows/WSL2 Docker Desktop host with the amd64 image, while the arm64 image on Apple Silicon was unaffected. Unconfining seccomp keeps Chromium's sandbox enabled (unlike the previously documented `CHASER_EXTRA_ARGS: "--no-sandbox"` fallback, which now also actually reaches the browser — see the `arachnea-http` entry) and needs no host-side configuration, which matters because WSL2's managed VM exposes neither `kernel.unprivileged_userns_clone` nor a settable AppArmor profile. `README.md` documents the required option for the Compose and plain-`docker run` paths, and the stale "no `--no-sandbox` needed, the sandbox works out of the box" claims in the `Dockerfile` and `docker-entrypoint.sh` comments were corrected.
- The `apt` layer ends with a file-presence check rather than executing Chromium under foreign-architecture emulation, where Rosetta on Apple Silicon lacks Chromium's required SSE3 CPU feature.
- `arachnea-docker/docker-entrypoint.sh` no longer reuses `DISPLAY=:99` on the lock file alone: it verifies that an Xvfb process is actually alive, purges a stale `/tmp/.X99-lock` (leftover from a dead Xvfb, since `/tmp` survives `docker restart`) with its socket before starting a fresh server, and warns when the fresh server fails to come up instead of handing headed Chromium a dead `DISPLAY`.
- An image built from a Windows working tree (`core.autocrlf=true`, no
  `.gitattributes`) never started: tini restart-looped with `exec
  /usr/local/bin/docker-entrypoint.sh failed: No such file or directory`
  because the copied entrypoint carried CRLF line endings (shebang
  `#!/bin/sh\r`). A root `.gitattributes` now pins `*.sh` and `Dockerfile`
  to LF on every checkout (`*.cmd`/`*.bat` stay CRLF), and the `Dockerfile`
  strips a trailing CR from the entrypoint's first line at `COPY` time so
  working trees checked out before that pinning still build a working image.

### <u>arachnea-core</u>

#### Added

- Added two-level SQLite persistence: `SqliteStoreConfig` / `SqliteDatabase` own a physical database and shared connection, while `PersistenceTableConfig` / typed table views manage independent entity schemas. `PersistenceStoreConfig` remains a compatibility alias for table configuration.

#### Changed

- Simplified ASCII-insensitive content-type checks, route-pair capacity calculation, API-prefix matching, log token splitting and private SQLite fixture path arguments. Header precedence, route order, log matching and stored paths are unchanged.
- Simplified default mode selection, snapshot loopback detection and the tray shutdown call, preserving the existing controller defaults and lifecycle.
- Reduced the controller and Tauri `mod.rs` files to module declarations and compatibility reexports. Separated shared contracts, typed registration, backend construction and REST settings; split native service state, dispatch, assets, runtime setup, IPC, custom-protocol routing and binary response buffering into private modules. The six existing settings tests now mirror `controler/rest_settings.rs`. Existing command/ETag contracts, call-site Tauri context generation, mount precedence, main-thread behavior and tracing targets are preserved.
- Split typed persistence into private schema, document, memory and file modules with compatibility reexports. Moved the ten existing backend scenarios to their exact source mirrors and shared entity helpers to `tests/support/typed_store.rs`; store contracts and persisted formats remain unchanged.
- Split SQLite schema reconciliation and entity/SQL conversions into private `sqlite_store/schema.rs` and `sqlite_store/conversion.rs` modules, keeping each file below 1,000 lines and preserving public import paths, feature gates, persistence formats and runtime behavior.
- Moved the unchanged embedded log-window page to crate-root `resources/log_window.html` and updated its `include_str!` path and documentation. Shared server agent instructions now require crate-owned resource files under `resources/`, with test-only fixtures remaining under `tests/fixtures/`.
- Moved the five existing unit-test suites into exact source-path mirrors under crate-root `tests/`, with shared temporary-directory helpers in `tests/support/`. Split REST snapshot/reply adaptation and Tauri configuration into private modules, preserving public reexports and runtime behavior. Centralized constants and relevant defaults in `src/lib.rs`, retaining feature/platform gates and distinct controller defaults, and extracted the unchanged log-window HTML as a compile-time asset. All Rust files now fit within 1,000 lines. Corrected the existing data-path doctest to configure its application identifier first and documented the prerequisite; 31 SQLite-enabled unit tests, 22 tests without SQLite, 11 doctests and 132 proxy consumer tests pass, with validation details in `docs/dev-tracking/harmonisation-crates-rust-lot1.md`.
- Reduced grouped SQLite key reads from 128 to 32 keys per chunk after finite reader/writer comparisons on synthetic 0/69/1,024-entry eviction tables. Shared-connection write medians improve from about 1.6 ms to 0.3 ms in the focused comparison, with less than 1 ms median read overhead; commit serialization, expiration and cancellation semantics stay intact. All 31 core and 132 proxy tests pass; sustained fairness and API gains remain unqualified.

- AES-GCM persistence nonces are generated directly with `rand::random()` instead of zero-initializing and then filling a buffer. Both paths retain uniformly random 12-byte nonces from the same thread-local cryptographic generator; encrypted formats remain unchanged.

- Added ordered typed `get_many` reads with scalar backend compatibility and bounded SQLite composite-key queries. SQLite releases its connection lock between chunks, checks expiration before entity decoding and documents partial cleanup/error/cancellation behavior; no cross-call caching or schema migration is introduced.

- SQLite files now use flat `<data-root>/<STORENAME>.sqlite3*` paths instead of `<STORENAME>/records.sqlite3*`. Legacy data is not imported or automatically deleted; newly persisted data survives restarts.

- `get_application_resource_path` now probes the release layouts (portable folder, macOS `Contents/Resources`, Linux system resource dir) for the requested relative path itself (file or directory) instead of resolving a cached resource root from a `services` directory check; `get_application_resource_root` was removed accordingly.
- Corrected the public rustdoc of `arachnea-core` after the crate refactorings: added `# Arguments`/`# Errors` contracts for typed persistence, stores, application and controller APIs, and fixed the four broken intra-doc links. No signature or runtime behavior changed; `cargo doc` passes with and without `sqlite-persistence`.
- Completed the global rustdoc review of `arachnea-core`: documented the remaining private application, controller, REST supervisor/service/tray, file-codec, SQLite and typed-store helper parameters, with ordered `# Arguments` and contextual `# Errors` where the path is fallible. No signature or runtime behavior changed; the final six-crate scan reports zero missing or obsolete argument entries for Core.

#### Fixed

- The exported controller macro now resolves `ApplicationMode` through its defining crate, so callers no longer need that type imported at their crate root. Simplified URL-query fallback construction and made existing SQLite test lock scopes and single cancellation polling explicit without changing assertions.
- Removed the obsolete debug/desktop default-mode paragraph attached to controller options; runtime mode selection is unchanged.
- Removed redundant terminal returns in macOS controller shutdown/tray paths and derived `ApplicationMode::Default` with the existing `Server` default, without changing lifecycle or mode selection.
- Separated the debug-resource-path paragraph from the preceding rustdoc list, resolving its `doc_lazy_continuation` warning without changing behavior.
- Compile the typed-query predicate accessor only with `sqlite-persistence`, matching its sole SQLite consumer and avoiding dead-code warnings in minimal builds.
- SQLite column/index metadata and managed-index cleanup are scoped to each table, preventing schema reconciliation from modifying other tables in a shared store. Schema changes commit transactionally.
- Shared SQLite tables now use unambiguous, reserved-prefix managed index names: table `a_b` / column `name` no longer collides with table `a` / column `b_name`. Opening a table replaces its previous managed index names without changing records or external indexes; existing fixtures cover collision, reopening and reconciliation.
- REST route registration now builds a balanced Warp filter tree instead of a linear chain. Registration priority and client ACL checks are preserved, while polling depth grows logarithmically; this reduces stack pressure during nested proxy/TLS operations implicated in macOS debug stack-overflow reports.

- Linux resource probing now prefers the AppImage mount root (`$APPDIR/usr/lib/*/services`): the resolution previously derived `../lib` from the executable path alone, which resolved to `/tmp/.mount_.../usr/bin/services` (missing) instead of the Tauri bundler layout `$APPDIR/usr/lib/<product>/services`. deb/rpm probing via the executable path is unchanged.

### <u>arachnea-dns</u>

#### Changed

- Simplified blank-line printing in examples and copied the existing `Copy` DNSSEC state directly, preserving output and profile settings.
- Return DNSSEC NSEC proofs as the branch result directly, preserving the feature-disabled fallback and proof extraction behavior.
- Moved the eleven existing DNS test scenarios out of `src/` into exact source-path mirrors for core configuration, cache, resolution and server configuration, preserving function names, assertions and feature gates while updating module-qualified test names. Centralized 46 internal defaults and operational limits in `src/lib.rs` without changing values, resolver decision order, per-core cache defaults, TLS policy, listener exposure or public configuration contracts.
